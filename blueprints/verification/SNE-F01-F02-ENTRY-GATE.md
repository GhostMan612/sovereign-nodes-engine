# F-01 — Explicit admission to F-02 and later test lanes

## Minimum F-02A (read-only metadata) prerequisites

- Dated, signed operator `AUTH-H` for the named device, exact redacted fields and read-only operations.
- Non-invasive technique and local paths selected, with no dependency installation, game launch or private-data access.
- Independent reviewer may remain pending only if the **operator's** host metadata authorization explicitly treats inventory as preparatory and non-acceptance; G7 stays OPEN.

## Minimum F-02B synthetic fixture prerequisites

- Separate `AUTH-F` with exact off-repo writable sandbox, original source SHA, B0/B1/B2 mutation manifest and no real genealogy.
- Separate `AUTH-T` if any game runtime will be launched; a fixture preparation approval cannot authorize a run.
- Lawful resource rights and original PK3 SHA if used; if unknown, case is `BLOCKED` and only source review can proceed.
- Explicit original-game vs fixture negative controls and safe rollback; no global installs/changes.

## Other future gates

- F-03 candidate build needs `AUTH-B` plus approved dependency provenance and toolchain inventory.
- F-04 C-001…C-008 needs `AUTH-T`, original B0 SHA and lawful external IWAD.
- F-05 UHD 620 benchmark needs approved performance thresholds and `AUTH-P` **after valid parity**.
- F-06 source-only security/legal review needs its own `AUTH-S` and a qualified reviewer; distribution requires separately approved `AUTH-D`.
- F-07 accepts reviewed evidence; operator signs ADR-SNE-002 only if G1–G7 pass. Phase 01 `AUTH-I` remains a separate scope, not part of this sequence's automatic outcome.

## What F-01 v1.0.0 accomplished

Only *designing* these admission contracts and preparing request forms. No reviewer was appointed, no machine inventoried, no fixture generated, no code compiled and no engine chosen. The operator may now select a next narrow **proposal** rather than blanket-authorizing all cases.
