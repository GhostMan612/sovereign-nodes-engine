# F-03 → F-04 — Hard runtime admission boundary

A future candidate can request **F-04 gameplay parity** only after:

- Actual successfully built executable and runtime resource identities with hash, source/configuration/toolchain provenance and adequate G4 reviewer confidence.
- Lawfully obtained official IWAD (private provenance + hash) and the **unchanged original B0 game PK3** (SHA-256, canonical build provenance); no files embedded in public SNE docs/ZIP.
- Case C-001 unique GapNode title + distinctive geometry/actor and a no-PK3 negative control established as the oracle; don't accept vanilla Entryway fallback.
- Exact game/test case/C-001…C-008 plan, source and binaries, renderer choice, session length and redaction approved under **separate `AUTH-T`**. Builds do not imply permission to launch.
- Individual sprite, GLDEFS and handoff hypotheses remain actual unknowns until approved runtime controls; a synthetic fixture passing does not retroactively prove B0.
- Independent F-00 review and G1/G2/G6 concerns logged with operator disposition; critical legal/security blocks remain hard.

**If any identity/consent/resource is missing, F-04 remains BLOCKED/NOT RUN.** BiasedDoom optional glTF, voxels and GPU profiling require distinct later authorization. GZDoom first is a verification ordering preference, never foundation selection.
