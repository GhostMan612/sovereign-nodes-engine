# WO-E — Evidence-gated decision control flow

## Primary path

`A–D source research published → E author challenge → independent reviewer → operator approves isolated test scope → native build evidence → C-001…C-008 gameplay parity → UHD 620 P0 & profile traces → SBOM/security/fork maintenance → independent second-pass review → operator decides ADR-SNE-002 → separately authorize Phase 01.`

Each arrow is a gate, not an inference; failures branch into revised fixture, source pin, work order or candidate rejection. Completing WO-E can result in **research-document acceptance** while all technical gates stay open.

## Candidate logic

- If no candidate passes P0 core parity and licensing, status **NO SELECTION**; first discriminate project fixture defects from candidate incompatibility.
- If only one candidate passes hard gates, still require independent risk, update burden, reproducible build and UHD 620 evidence before adoption.
- If multiple pass, use `SNE-000E-FOUNDATION-SCORECARD.md` after measurements and record operator tolerances and normalized observations.
- If none meets modern graphics requirements but one passes P0, a P0-only interoperability baseline can be considered **only as a separate documented option**, not implicit final choice.
- If all fail fundamental rights or supportability, open separate clean-engine feasibility ADR. Do not silently rewrite Doom functionality in Phase 00.

## Authority

Research author can draft conditional decisions; independent reviewer can recommend; only operator can accept risk, choose engine, approve source modifications or initiate a future execution order.
